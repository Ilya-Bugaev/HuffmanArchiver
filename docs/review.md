## 1.Цель работы
Создать консольное приложение на языке C, которое по аргументам командной строки выполняет сжатие или разжатие произвольного файла с использованием алгоритма Хаффмана, а затем экспериментально оценить качество полученной реализации: определить коэффициент сжатия и пропускную способность для файлов различных типов и объёмов, провести многократные замеры с расчётом статистических характеристик и визуализировать результаты в виде графиков.

## 2. Теоретическая часть
Идея алгоритма. Равномерное кодирование (8 бит на байт) заменяется неравномерным: часто встречающиеся байты получают короткие коды, редкие - длинные, за счёт чего средняя длина кода оказывается не больше 8 бит, а для данных с неравномерным распределением байтов - строго меньше. Символом считается один байт (значение от 0 до 255), что позволяет одинаково обрабатывать и текстовые, и произвольные бинарные файлы.

1. Подсчёт частот. По файлу подсчитывается частота каждого из 256 возможных значений байта; для каждого встретившегося байта создаётся листовой узел дерева.

2. Построение дерева. Узлы помещаются в приоритетную очередь по частоте. Дерево строится итеративным слиянием: на каждом шаге из очереди извлекаются два узла с наименьшей частотой, объединяются в новый внутренний узел с суммарной частотой, результат возвращается в очередь - пока не останется единственный узел, корень дерева. При очереди на основе двоичной кучи построение укладывается в O(n log n), где n - число различных байтов в файле.
3. Формирование кодов. Дерево обходится от корня: левому переходу соответствует бит 0, правому - 1, код символа - путь до соответствующего листа. Такая схема гарантирует префиксность кодов (код одного символа никогда не является началом кода другого), благодаря чему декодер однозначно определяет границы символов в битовом потоке без разделителей.

4. Вырожденный случай. Если файл пуст, архив содержит только заголовок без сжатых данных. Если в файле встречается единственный уникальный байт, дерево состоит из одного узла, и стандартный обход не порождает кода; в реализации для такого символа явно фиксируется код длиной 1 бит.

5. Сжатие. Вторым проходом по файлу каждый байт заменяется его кодом; биты накапливаются в буфере и побайтово пишутся в выходной поток, а хвост дописывается нулями. Таблица частот и исходный размер файла записываются в заголовок архива - без исходного размера при разжатии невозможно отличить значащие биты от дополняющих нулей в конце потока.

6. Разжатие. Дерево восстанавливается из таблицы частот, сохранённой в заголовке. Сжатые данные читаются побитово: каждый бит определяет спуск по дереву от корня (0 - влево, 1 - вправо), при достижении листа символ записывается в выходной файл, и обход возобновляется от корня - до тех пор, пока не будет восстановлено исходное число байт.

## 3.Существующие реализации

- SmnTin/huffman-archiver (C++) - каноническое кодирование Хаффмана, оптимизирован для больших файлов: не грузит их целиком в память, ~195 МБ/с на сжатии. (язык - C++, не C: используются std::ifstream/std::ostream и другие C++-конструкции)

- aedobrynin/huffman-archiver (C++) - CLI-архиватор с поддержкой нескольких файлов в одном архиве, покрыт тестами.

- cuklev/huffman-archiver-cpp (C++) - простая реализация со сравнением коэффициента сжатия против lz4 на разных типах данных.

- isebasus/archive (C) - две отдельные программы, encode и decode, работающие через пайпы (./encode < file | ./decode), сборка через Makefile и Clang.

## 4.Ожидаемые результаты экспериментов

Коэффициент сжатия (отношение размера архива к размеру исходного файла):
Текстовые файлы (ASCII): ожидается уменьшение до 40–55% от исходного размера.
Текстовые файлы (UTF-8, кириллица): 50–65% из-за двухбайтового представления символов.
Бинарные файлы с неравномерным распределением байтов (BMP, WAV): 70–85%.
Уже сжатые файлы (ZIP, JPEG, MP4): 95–100% или даже увеличение размера, поскольку данные уже имеют высокую энтропию.
Файлы менее 1 КБ: возможно увеличение размера из-за накладных расходов на хранение заголовка.
