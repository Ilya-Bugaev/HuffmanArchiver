## О проекте

Консольный архиватор на языке C для сжатия и разжатия файлов без потерь на основе алгоритма Хаффмана. Приложение сжимает и восстанавливает файлы любых типов: текст, изображения, аудио и произвольные бинарные данные.

Символом считается один байт (значения 0–255). По частотам байтов строится дерево Хаффмана, часто встречающиеся байты получают короткие коды, редкие получают длинные. Файл читается блоками по 64 КБ в два прохода, поэтому его размер не ограничен объёмом памяти.

Материалы практики лежат в каталоге [`docs`](docs): [обзор](docs/review.md). Скрипты и результаты измерений находятся в [`experiments`](experiments).

## Возможности

- Сжатие произвольных файлов по алгоритму Хаффмана
- Разжатие с восстановлением исходного содержимого
- В заголовок архива записываются исходный размер и дерево Хаффмана
- Поддержка файлов любого размера и типа (текст, бинарные данные), включая пустой файл и файл из одного уникального байта
- Результат пишется во временный файл и заменяет выходной только после успеха, поэтому при ошибке существующий файл назначения не портится, а входной и выходной пути могут совпадать

## Сборка

Требуется компилятор C с поддержкой C17 (проверялось на gcc 13.3.0) и CMake версии 3.16 или новее. Сборка рассчитана на Linux (используются POSIX-функции `mkstemp`, `fchmod`, `fdopen`).

```bash
git clone https://github.com/Ilya-Bugaev/HuffmanArchiver.git
cd HuffmanArchiver
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build
```

После сборки в каталоге `build` появляется исполняемый файл `huffman`.

## Использование

```text
./build/huffman c <входной_файл> <выходной_архив>    сжать файл
./build/huffman d <входной_архив> <выходной_файл>    разжать файл
```

Пример:

```bash
./build/huffman c book.txt book.huf
./build/huffman d book.huf book_restored.txt
cmp book.txt book_restored.txt && echo "файлы совпадают"
```

При ошибке программа печатает сообщение в `stderr` и завершается с кодом 1.

## Тесты

```bash
ctest --test-dir build --output-on-failure
```

Проверяются приоритетная очередь, дерево Хаффмана, побитовый ввод-вывод, сжатие, разжатие и полный цикл «сжать, разжать, сравнить побайтово».

### Санитайзеры и Valgrind

Сборка с AddressSanitizer и UndefinedBehaviorSanitizer:

```bash
cmake -B build-san -DCMAKE_BUILD_TYPE=Debug -DENABLE_SANITIZERS=ON
cmake --build build-san
ctest --test-dir build-san --output-on-failure
```

Проверка утечек и ошибок работы с памятью через Valgrind:

```bash
cmake -B build-vg -DCMAKE_BUILD_TYPE=Debug
cmake --build build-vg
ctest --test-dir build-vg --output-on-failure -T memcheck
```

Оба режима запускаются в CI отдельным заданием.

## Устройство проекта

| Модуль | Назначение |
|---|---|
| [`src/main.c`](src/main.c) | Разбор командной строки: режим `c` или `d`, входной и выходной файлы |
| [`src/priorityQueue.c`](src/priorityQueue.c) | Мин-куча узлов по частоте, `push` и `pop` за O(log n) |
| [`src/huffmanTree.c`](src/huffmanTree.c) | Узлы дерева, построение по частотам, таблица кодов, запись и чтение дерева |
| [`src/bitStream.c`](src/bitStream.c) | Побитовая запись и чтение через буфер |
| [`src/compress.c`](src/compress.c) | Сжатие: подсчёт частот, запись заголовка, дерева и кодов |
| [`src/decompress.c`](src/decompress.c) | Разжатие: чтение заголовка и дерева, декодирование битов |
| [`src/tempOutput.c`](src/tempOutput.c) | Временный выходной файл и его подмена через `rename` после успеха |

Формат архива:

```text
[8 байт]  размер исходного файла (uint64, little-endian)
[биты]    дерево Хаффмана в порядке preorder: лист = бит 1 и 8 бит значения байта,
          внутренний узел = бит 0, затем левое и правое поддеревья
[биты]    сжатые данные (левый переход = 0, правый = 1)
[биты]    нулевые разряды до границы байта
```

Пустой файл кодируется 8 нулевыми байтами без дерева и данных. Если в файле один уникальный байт, дерево состоит из одного листа, и для этого байта фиксируется код длиной 1 бит.

Подробности интерфейсов модулей описаны комментариями в заголовочных файлах `src/*.h`.

## Стиль кода

Форматирование задаёт [`.clang-format`](.clang-format), статические проверки задаёт [`.clang-tidy`](.clang-tidy). Оба инструмента запускаются в CI, ошибка останавливает сборку. Локально:

```bash
clang-format-18 --style=file -i src/*.c src/*.h tests/*.c experiments/*.c
clang-tidy-18 -p build src/*.c
```
